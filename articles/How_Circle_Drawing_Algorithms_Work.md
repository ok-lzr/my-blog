# 画圆算法是怎么画圆的

屏幕上的圆，其实是一堆按规律排布的小方格（像素）。问题是：怎么决定哪些像素该点亮？最朴素的想法是"把方程上的每个点都算出来"，但浮点运算慢、还容易产生断点。真正的经典解法，是只做整数加减法的**中点画圆法**。这篇文章从方程出发，一步步把它推导出来。

## 圆的两种数学表达

画圆首先要有圆的方程。常用的有两种：

- **标准方程**：`x² + y² = r²`。给定 x 求 y 需要开方，产生浮点运算。
- **参数方程**：`x = r·cosθ`，`y = r·sinθ`。θ 从 0 扫到 2π，需要三角函数。

直接按这两种方程逐点采样都能画出圆，但每画一个点都要做浮点计算。在 90 年代的低性能设备上，这很奢侈。于是人们想到了用"判断 + 递推"来代替"计算"。

## 利用 8 对称性：只算八分之一

圆关于两条坐标轴和两条对角线对称。只要画出第一象限 45° 的弧，其余 7 段都能通过镜像得到。也就是说，每确定一个点 `(x, y)`，就可以同时画出 8 个点：

```c
void plot8(int xc, int yc, int x, int y) {
    putPixel(xc + x, yc + y);
    putPixel(xc - x, yc + y);
    putPixel(xc + x, yc - y);
    putPixel(xc - x, yc - y);
    putPixel(xc + y, yc + x);
    putPixel(xc - y, yc + x);
    putPixel(xc + y, yc - x);
    putPixel(xc - y, yc - x);
}
```

这直接让计算量缩小到原来的八分之一。

## 中点画圆法（Bresenham 圆算法）

核心思路：从 `(0, r)` 出发，x 每次加 1，y 保持或减 1——具体是哪个，取决于"下一个理想点落在两个候选像素中点的哪一侧"。用函数 `f(x, y) = x² + y² - r²` 判断：点在圆内为负，圆外为正，正好在圆上为 0。

定义决策参数 `p` 为"候选中点"处的函数值。可以证明（推导从略）：

- 初始值 `p = 1 - r`（取整后），`x = 0`，`y = r`。
- 若 `p < 0`：中点偏内，选 `(x+1, y)`，`p += 2x + 3`。
- 否则：中点偏外，选 `(x+1, y-1)`，`p += 2x - 2y + 5`。

整个过程只有整数加减，没有乘法、开方或三角函数。完整代码：

```c
void drawCircle(int xc, int yc, int r) {
    int x = 0;
    int y = r;
    int p = 1 - r;              // 决策参数初始值

    while (x <= y) {
        plot8(xc, yc, x, y);    // 一次画 8 个对称点
        x++;
        if (p < 0) {
            p += 2 * x + 1;     // 选择正右方像素
        } else {
            y--;
            p += 2 * (x - y) + 1; // 选择右下方像素
        }
    }
}
```

（上式把推导中的 `2x+3`、`2x-2y+5` 换成了先自增 x 后的等价形式 `2x+1`、`2(x-y)+1`，两者结果一致，后者更常见。）

## 几种方法的对比

| 方法 | 运算 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 参数方程采样 | 三角函数、浮点 | 直观，角度可控 | 慢，点密度不均匀 |
| 标准方程采样 | 开方、浮点 | 实现简单 | 慢，容易产生空隙 |
| 中点画圆法 | 整数加减 | 极快，无浮点，均匀无断点 | 只画实心圆边界，思路稍绕 |

## 一点延伸：抗锯齿

中点画圆法画出的圆在斜边上会有明显的"锯齿"（像素台阶）。现代渲染会用超采样（把每个像素再细分后平均）或多级灰度近似来处理。理解了中点法的"点选"逻辑后，这些进阶方案其实都是在"选哪个像素"和"涂多亮"之间做权衡。

## 结语

中点画圆法的高明之处，是把"求精确交点"的问题转化为"判断偏差符号"的问题，再用递推把计算量压到纯整数加减。这正是计算图形学的魅力：用巧妙的数学变换，把昂贵运算变成廉价判断。下次看到屏幕上一个光滑的圆，你可以想想——它可能只是几百次整数加法拼出来的。
