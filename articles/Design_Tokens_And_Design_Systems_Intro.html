设计系统入门：用设计令牌统一多端体验

2026年9月20日
阅读时间：9 分钟
设计系统 设计令牌 前端

当一个产品从单个页面长成多个端、多个团队协作时，"设计不一致"就成了必然的熵增：按钮圆角三种、主色两套、间距全凭手感。设计系统的价值，就是把这些隐性约定变成显式、可复用、可演进的资产。这篇文章聊聊最小可落地的路径。

什么是设计系统

设计系统不是一套 UI 组件库，也不是一份设计规范文档。它是两者的结合，再加上支撑它们的工具链与协作流程：原则 → 令牌 → 组件 → 模式 → 文档。上层越抽象越稳定，下层越具体越易变。而一切的基石，是设计令牌。

设计令牌：给决策命名

设计令牌（Design Tokens）把颜色、字体、间距、圆角等设计决策存成带语义的变量。关键在于"语义化"——不叫"蓝色 #4a6fa5"，而叫"品牌主色"，这样换主题时只改一处：

:root {
    /* 原始值层 */
    --blue-600: #4a6fa5;
    --gray-900: #1a1815;

    /* 语义层：组件只依赖语义名 */
    --color-brand: var(--blue-600);
    --color-text-primary: var(--gray-900);
    --color-bg: #f7f2eb;

    /* 间距与圆角 */
    --space-1: 4px;
    --space-2: 8px;
    --space-3: 16px;
    --radius-md: 8px;
}

深色模式是最典型的收益场景：只要把 --color-bg、--color-text-primary 在 data-theme="dark" 下重新赋值，整个站点的明暗就瞬间切换，没有任何组件需要改动。

间距节奏：告别魔法数字

间距是页面"呼吸感"的来源。建议用 4 或 8 的倍数建立节奏刻度，组件内部只从刻度中取值，禁止随手写 padding: 13px 之类的魔法数字：

.card {
    padding: var(--space-3);        /* 16px */
    gap: var(--space-2);            /* 8px */
    border-radius: var(--radius-md);
}

节奏一旦统一，页面之间的对齐感会立刻提升——这是投入产出比最高的一步。

组件化：封装变化

组件库不是"把页面拆成组件"就完事了，关键是定义好变体（variant）和属性接口，把允许的变化收进白名单：

  • 尺寸：sm / md / lg，对应固定的高度与内边距。
  • 外观：primary / secondary / ghost，只允许预设的几种组合。
  • 状态：hover、focus、disabled、loading 必须成体系地定义。

白名单之外的变化，就应该回到设计侧讨论，而不是在代码里开"后门"。

落地工具与流程

环节推荐做法
令牌管理单一 JSON 源，经 Style Dictionary 编译为 CSS / SCSS / 原生变量
组件开发Storybook 或同类工具，组件即文档
规范沉淀使用规范与更新日志随仓库版本管理
变更流程先改令牌 → 同步组件 → 全站回归，禁止绕过系统"硬编码"

结语

设计系统不是一次性的"大工程"，而是一个持续演进的契约。即使只有一个人维护一个小站（就像本站），从颜色令牌和间距刻度开始，也能让后续的每次改动都更快、更一致。先建立最小体系，再让它随产品一起成长。
